# B站视频 → 题库题目（开发期内容生产 skill）

把 B站 何切 / 牌效率视频里的自由文本，变成能过 `bank:verify` 的原创题目。
**这不是用户功能**：没有任何页面、页签、录入 UI——产出只落 `content/questions/` + 文档。
**机械部分是现成脚本，不是新写脚本**：本 skill 只做语言理解 + 编排 + 守红线。

## 角色与铁律

| 谁 | 干什么 |
|---|---|
| Claude | 拆手牌 / 识别视频论点 / 写原创讲解 / 裁决口径（与用户往返） |
| 脚本（现成） | 数字与查重唯一裁判：`probe.ts` / `refine.ts` / `skeleton-check` / `nearcheck` / `bank:verify` |

铁律（任何一步都不可违反）：
1. **数字纪律**：向听数、进张张数一律来自引擎输出（`probe` / `bank:verify`），**禁止心算**。
2. **不一致必须停下讨论**：视频答案不在引擎最优集合里 → 摊开候选表问用户，**不擅自替用户裁口径**。
   裁决若改变判分口径 → 落 `docs/decisions.md`；纯一题「待讨论」→ 不入库。
3. **不碰** `packages/engine/**`、`apps/web/**`、判分口径。题库 Schema 的真身在
   `packages/engine/src/verify.ts` 的 `Question` 接口 + `apps/web/src/lib/types.ts`（全量字段），
   校验以 `bank:verify` 通过为准。（注：CLAUDE.md 引用的 `content/schema/question.schema.json`
   在仓库中不存在，是文档债，别去找它。）
4. **原创讲解**：只参考视频的牌例与论点，不复制其长句文案；用词守 vocabulary 红线
   （胡牌→和了、卡张→嵌张、单吊→单骑、对倒→双碰、组牌→面子、将→雀头、塔子→搭子、
   拆塔→拆搭、受入/有效牌→进张、孤张→浮牌、复合型→复合牌、退向听→向听倒退；主名权威见
   `docs/vocabulary.md`）。
5. **展示层中文记法**：题面/讲解用 `3万 456筒 789条`，顺序 万→筒→条、同花色升序；引擎/JSON
   内部才用 `3m 6p` 码。

## 主流程（8 步）

### 1 拆题 —— 语言理解
从视频文本里识别，每手牌产出四条，**先复述给用户确认，再跑引擎**：
- **手牌 14 张**：把口语牌型转成有序码。常用句式 → 码：
  - 「3万」「六筒」「2条」→ `3m 6p 2s`；「三四五万」/「345万」→ `3m 4m 5m`
  - 「一对 6 万」/「66筒」→ `6m 6m`、`6p 6p`；「两对半 6677」→ `6p 6p 7p 7p`
  - 口语含糊（例「有个 456 条的顺子」但没说哪几张）→ 列出你的理解并追问，凑不满 14 张别往下走
- **视频答案**：UP 主让切哪张（或「打 X」），原样记下
- **核心论点**：这一手在教什么（考点名，如「两对半：先拆对还是拆两面」）
- **出处**：视频标题（进第 8 步登记用）

### 2 对拍 —— 引擎是裁判
```bash
npx tsx content/build/probe.ts "2s 3s 6s 6s 7s 7s 9s 9s 3m 3m 4m 5m 6m 7m"
```
probe 会打印：`最优 [..]` + 不退向听切法数 + 最优/次优张数差 + 完整候选表（前 8）。
数字只认这里。

### 3 判定：一致 / 不一致
- **一致** = 视频答案 ∈ 引擎最优集合，且引擎并列最优全都被视频答案覆盖 → 照录。
- **不一致** → **停下**，把引擎最优 `[..]`、候选表、视频答案三样摊给用户讨论：
  - 先分辨视频理由属不属于 **V1 不判分维度**：打点/宝牌、安全/攻守、引挂/巡目、七对、
    他家可见牌推论、地方规则——这些只进讲解，不改变 `correct`。
  - 若可重铸成纯牌效可判题（换副牌/换措辞）→ 与用户确认后重铸；
  - 若必须靠不判分维度才能自圆其说 → 按用户裁定标「待讨论」暂不入库，或干脆弃题。
  - 结论动了判分口径才写 `docs/decisions.md`（倒序）；单题裁量不用写。

### 4 归分类 + 定级
**category**（5 枚举，人工判定，判据按序，出处 `vocabulary.md §二`）：
1. 主角是一个**形状**（中膨/亚两面/两对半/两嵌/四连/五连…）→ `composite`
2. 主角是**听牌后的形式**（两面 vs 单骑、留法选择、多面张）→ `tenpai`
3. 主角是**整手结构**（块数/对子数/搭子过剩 vs 对子过剩、先拆谁的整序）→ `structure`
4. 是**跨形状取舍原则**（不倒退/愚形让位/浮牌先走/并列怎么看）→ `strategy`
5. 只教**认出单位/算张数/比价值** → `basic`
   顺序命中即归；「两对半：搭子 vs 对子谁先动」的整手取舍 → `structure`。
**level**（L1–L7，主题见 `apps/web/src/lib/levels.ts`）：
L1 基本形识别 / L2 搭子价值与进张 / L3 复合形与多面张 / L4 五搭子与拆搭(整手组织) /
L5 一向听与听牌选择 / L6 改良与向听倒退 / L7 综合。主考点落在哪级就标哪级，
新题别硬塞更高一级——贴现有同考点题的级别（`content/questions/L*.json` 可查）。
**difficulty**（易/中/难，编辑主观但求一致）：用 probe 的画像行参考——不退向听切法 ≥2 且
最优/次优差 1-2 张 → 通常 `hard`；贴近 `nearcheck` 提示的既有同考点题。

### 5 写讲解（原创，三段式）
`explanation` 至少给 `best`（主体讲解）与 `source`。讲解要覆盖：为什么切它（不退向听 +
张数口径）、对比次优差多少张、一句话口诀。可加 `ukeire_table` 的 `note` 逐行点破陷阱
（字段见 `apps/web/src/lib/types.ts`；进张对比表本身由 `engine_snapshot` 自动渲染，别手写进张表）。
`source` 出处行格式：`B站·<视频标题>`（不标 UP 主引战类描述、不写页码）。

### 6 查重双闸（入库前必跑，两闸全过才继续）
拿步骤 1 的手牌码（`<14 张>`）与核心论点关键词（`<kp>`）跑：
```bash
npx tsx content/build/skeleton-check.ts "<14 张>"
# 换皮撞车 → 直接否决（与题库手牌同骨架 = 用户会觉得做过这题）

npx tsx content/build/nearcheck.ts "<14 张>" --kp "<核心词 空格分隔>"
# 考点近亲（骨架不同但练同一件事）→ 提醒人工取舍，命中就逐一对比，撞就换
```
两闸全过才继续；被否决就换牌例或放弃，别硬塞。同考点已有的题宁可做「结构变体」，不重复。

### 7 入库
- 追加进 `content/questions/L{n}.json`（数组）；`id = L{n}_{NNN}` 取该文件下一个空号（先数现有最大号）。
- 按 `verify.ts` 的 `Question` 接口填字段；`what_to_discard` 的 `hand` 须 14 张、按
  万→筒→条各花色升序排；`answer.correct` **先照抄引擎最优全集合**（并列全列）。
- `engine_snapshot`/`verified` 不手写——交给校验注入：
```bash
npm run bank:verify -- --write        # 全绿即自动写回 engine_snapshot + verified
```
被拒就照错误改（常见：correct 非最优 / 并列没列全 / category 非枚举）。

### 8 收尾
- 出处登记：首次引用的视频在 `docs/references/SOURCES.md` §二（在线使用、不落盘）补一行；
  §五勾稽表只登记文档正文引用过的理论出处，视频标题不进。
- bump `content/build/version.mjs` 的 `CURRENT_BANK_VERSION` → `npm run bank:roll`
  → `npm run bank:dist`（题量分布过闸门）。批量录入时**每一步先给用户看 diff 再入库**。

## 每次执行必交的收尾汇报
- 拆出的手牌码 + 视频答案 + probe 最优（含 margin 行）
- 判定结论：一致照录 / 不一致(列出讨论结果)
- 落库 id + category + level + difficulty + source
- 两闸 + `bank:verify` + `bank:dist` 结果；动了文档（decisions/SOURCES/version）也列出来
