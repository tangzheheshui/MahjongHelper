## 二、关键实现要点

### 1. 牌面渲染：单组件接口 + 两级皮肤（定案）

**架构**：所有页面只消费一个 `<Tile id="3m" size={} selected={} />` 组件，SVG 实现，
皮肤（skin registry）可整体替换。这样"像不像"是可以一直打磨的美术问题，而不再是架构问题——
换皮只动资产层，不碰任何页面代码。

**为什么 SVG 而不是 Unicode 字符 / 位图**：
- Unicode 麻将字符（🀇…）：各平台字体渲染不一致、样式不可控，否决
- 位图（PNG 贴图）：多倍率发虚、无法按主题调色、换皮成本高
- SVG：矢量无损（手牌 23px 到讲解区 96px 一套资产通吃）、体积小、可程序化调色

**牌面设计规范（v1 小样依据）**：
- 画布 2:3（viewBox 120×180），圆角 r≈10，遵循实物牌比例
- 牌体立体感：象牙白渐变面 + 底/侧两档厚度色 + 环境投影（投影由 CSS 层出，不烧进 SVG）
- 34 面内容按实物几何绘制：万（上数字下「萬」，數字黑、萬红，主流惯例）；饼（圆点阵列
  布局按实物，如 5 饼四角+红心）；索（节状竹条，1 索为雀鸟）；字牌（東南西北白發中，
  中红、發绿、白素面）
- **小尺寸硬约束**：手牌 14 张在 375px 屏宽下每张仅约 23px——此尺寸下"像"来自轮廓、
  图案几何与配色正确，而非纹理；渐变与雕刻感只在讲解区大尺寸（40-96px）显影。
  小样验收必须含 23px 渲染档
- 配色逐张对照实物照片/主流牌谱 UI 校准，小样阶段定稿

**质感目标（2026-08-31 与用户对齐）**：对标主流商业麻将游戏的渲染级观感——多层渐变、牌体厚度、
边缘高光、环境投影、雕刻感字形/图案；不做「扁平示意图」。

**牌面资产分工（2026-08-31 定，2026-09-02 更新）**：正式牌面美术由**用户经其他途径自筹**，
开发期 UI 使用占位牌面（见下方皮肤表），两条线并行、互不阻塞；若自筹最终不可得，回落本文
原方案（SVG 自绘铺满 34 张）。所有牌面统一经 `<Tile>` 组件渲染、皮肤可整体替换——无论最终
资产是 SVG / 位图 / 精灵图，接入只动 skin 层一个文件（素材许可须核验，见 SOURCES.md 红线）。

**资产许可红线**：不使用天凤/雀魂等商业游戏的牌面素材（质感可以对标，素材不搬运）；
开源图集必须核验许可并登记；自绘资产无许可负担（首选）。

**开发期两套皮肤（2026-09-02 定，当日按用户更正修订）**：

| 皮肤 | 内容 | 说明 |
|---|---|---|
| `placeholder` | 万/条 = `apps/web/scripts/tile-samples-v0.8.html` 定稿素材（行楷萬子 + 放大一索）；饼 = 五案选型定「丁·暗沉哑光」+ 实物排布修正（3p 斜排、7p 上斜下四不重叠、9p 3×3 小饼）；字牌明朝体 | 教学占位，全站默认；万/条素材经同目录 `extract-v08-tiles.mjs` 提取生成 `tiles/v08-faces.ts`，勿手改 |
| `classic` | 参考用户提供的实物图风格**原创重绘**（象牙白面、靛蓝饼、绿竹、朱红萬/中、一索雀鸟） | 不复制任何商业素材，遵守上方红线 |

- 选择持久化在 `nk.settings.tileSkin`，设置页可切换并实时预览；`<Tile>` 支持 `skin` 覆盖参数（预览用）
- 用户后续若自筹到有许可的正式资产，仍按「只动 skin 层一个文件」接入，两套开发期皮肤保留为内置选项

### 2. 判分与讲解数据

判分不实时算引擎：每题带 `engine_snapshot`（出题时已由 CLI 校验写入），客户端比对
`answer.correct` 即可（<1ms，PRD ≤1s 约束轻松满足）。引擎包仍随 App 内置（M2 起供水平测试
抽题、后期扩展用）。

### 3. 本地存储 Schema

| key | 存储 | 内容 |
|---|---|---|
| `nk.progress` | localStorage | 各级各关：完成状态、最高正确率、解锁位 |
| `nk.wrong_book` | localStorage | 错题 ID 列表 + 重做结果 |
| `nk.placement` | localStorage | 最近一次定级结果 + 日期 |
| `nk.settings` | localStorage | 用户偏好 |
| `nk.bank` | IndexedDB（库名 `nanikiru` / store `bank` / key `merged`） | 合并后的全量题库（内置 + 远程增量），含 bank_version |

题库读取带 1500ms 超时竞速：IndexedDB 回调悬挂（隐私模式 / 部分嵌入式 WebView）时静默降级
内置题库，功能不缺（2026-09-02 实测无头环境发现，落实为 `bank.ts` 的 `withTimeout`）。

### 4. PWA / 离线

- `vite-plugin-pwa` + Service Worker 预缓存 App 壳 + 出厂题库
- 断网时全部功能可用；联网时启动静默检查更新（失败无提示，PRD 6.4）

**题库增量更新（M4，2026-09-02 落地）**：协议与客户端状态机见
[architecture.md §五](docs/design/architecture.md)；实现收敛在 `lib/update.ts` + `lib/bank.ts`：

- **启动静默**：`App.tsx` 挂载后 fire-and-forget `checkBankUpdate()`，更新成功即清空题库缓存；
  任何失败吞掉不提示。只测逻辑不动 UI 的覆盖靠 `scripts/e2e-update.ts`（node http 干跑真实链路）。
- **设置页手动**：`题库` 面板「检查并更新题库」按钮，三种结果态：
  已是最新 / 已更新到 `{version}`（下载 N 个分片）/ 检查失败（保留本地题库）；成功就地刷新版本与题数。
- 题库读取与更新的 IndexedDB 访问带 1500ms 超时竞速，悬挂时静默降级内置（同 §二.3）。

### 5. 关卡抽题

每关题量 8-12（PRD 5.4）；题库不足允许复用题目并提示「该关卡题库较少，可能复现」（PRD 6.4）。

### 5a. 四种题型的作答交互（2026-09-02 定，M3 扩量先行）

PRD 5.5 四种题型全部进关卡池；**水平测试抽题池保持只抽 `what_to_discard`**
（定级要横向可比，何切是核心题型，见 `levels.ts` 现状）。

| 题型 | 交互 | 判定 |
|---|---|---|
| `what_to_discard` | 手牌点 1 张即判（现状） | `correct` 数组包含（并列全对） |
| `ukeire_compare` | 「二选一」切牌按钮（现状） | 单选 `discard` ∈ `correct` |
| `mentsu_identify` | 题干指定搭子类型（两面 / 嵌张 / 边张 / 对子之一），手牌中**点选 2 张**提交 | 所选两张**无序**等于 `correct[].tiles` 任一组即对；该类型全部合法组合必须全列（否则点中合法组被判错） |
| `wait_choose` | 听牌留法二选一：按钮文案 = `label`（如「切 2条 · 留两面」），判分用 `value` | 单选 `value` ∈ `correct`；两选项切后均须 0 向听，判定口径 = 进张张数（速度），打点差异只进讲解 |

- `mentsu_identify` 的 V1 简化：只做「指定类型的识别」，不做 PRD 5.5 的「找出所有搭子
  并分类」完整形态（多选 + 逐个分类交互 V2 再做）；识别出 35 与 53 的形状差异本身就在练分类。
- 讲解抽屉对 `mentsu_identify` / `wait_choose` **不显示切牌进张对比表**（快照语义不匹配），
  数字写进 `explanation.best` 文案；出处照常显示。
- `engine_snapshot` 只对 `what_to_discard` / `ukeire_compare` 注入（verify CLI 现状，保持）。

### 6. 自测通道（M2 起固定）

- **闭环冒烟**：`npx tsx apps/web/scripts/smoke-loop.ts` —— node 内存 localStorage 模拟
  练 → 判 → 讲 → 结算/解锁 → 错题本 → 水平测试 全链路（IndexedDB 缺席走内置降级，顺带覆盖离线口径），
  改 lib 层后必跑
- **题库更新双自测（M4 起，改 bank.ts/update.ts 后必跑）**：
  `npx tsx apps/web/scripts/e2e-bank.ts`（内存 fake-indexedDB 跑真实 loadBank/checkBankUpdate，
  覆盖 IDB 层）+ `npx tsx apps/web/scripts/e2e-update.ts`（node http 干跑
  manifest→增量→sha 校验纯逻辑链路）
- **渲染自测**：`vite preview` + Edge headless `--dump-dom` 核对五页关键内容与牌面 SVG 数量
- 结算/记错题逻辑收敛在 `lib/levels.ts` 的 `applyRunResult` 与 `lib/storage.ts` 的 `recordWrong`，
  页面只做展示层调用（保证冒烟测的就是线上跑的）

## 三、V1 不做（PRD 4.2 全文照抄执行）

对战 / 牌谱复盘 / 地方规则 / 赖子变体 / 账号系统 / 行为收集 / 每日一题打卡 / 成就排行榜 / 社交分享。

## 四、视觉基调（一句话）

内容工具感、非游戏化：浅色为主、大字号、牌面即视觉焦点；无动效依赖，答题反馈 ≤200ms。
